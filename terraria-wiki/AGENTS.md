# Terraria Wiki — AI 開發規範

## 目的與範圍
建立繁體中文、非官方 Terraria 攻略知識庫，供新手查閱，並保留未來 AI Companion 使用結構化資料的可能。以原版桌面遊戲為主，不混入模組或未驗證版本數值。

## 技術與結構
使用 HTML5、原生 CSS、JavaScript；不需框架、API 金鑰或後端。GitHub Pages 從根目錄部署。所有本地連結使用相對路徑。
- `index.html`：唯一入口與共用文章容器。
- `assets/css/style.css`：全站共用樣式。
- `assets/js/main.js`：搜尋、分類、路由與文章渲染。
- `data/articles.js`：文章資料，採 JSON 相容陣列，外層為 `window.ARTICLES = [...]`，讓本機直接開啟也能使用。
- `templates/article.json`：新增文章的資料範本，不直接載入網站。
- `README.md`：操作與部署說明。

## 視覺規範
背景 #101810、卡片 #1C2A20、主題 #81C784、強調 #FFD166、文字 #E8F0E8。使用系統字型、清楚的標題階層、8 至 16px 圓角與一致間距。桌面雙欄導覽，窄螢幕改單欄；不得為單篇文章另建 CSS。維持鍵盤可操作、可見焦點及文字對比。

## 文章資料契約
每篇文章必須包含 `id`（唯一英文 kebab-case）、`title`（繁中）、`english`、`category`、`stage`、`summary`、`tags`（字串陣列）、`sections`（含 `heading`、`body` 字串的物件陣列）、`sources`（含 `label`、`url` 的物件陣列）、`updated`（YYYY-MM-DD）。分類只能是 bosses、weapons、classes、progression。stage 使用「困難模式前」「困難模式後」「全階段」。
Boss 章節固定為召喚方式、戰前準備、戰鬥策略、掉落物；武器為取得方式、使用技巧、限制；職業為定位、裝備建議、玩法；進度為目標、行動順序、注意事項。內容以自己的文字撰寫，引用可靠來源，未確認的版本差異或掉落率不填，不複製整篇 Wiki。

## 新增與修改流程
1. 先閱讀本文件、範本與同分類既有文章。
2. 查證攻略來源，確認分類與遊戲階段。
3. 複製範本，填寫全部欄位，將新物件附加到 articles.js；不得重複 id。
4. 不需修改首頁、導覽或搜尋程式；它們由資料自動產生。文章網址為 `index.html#文章-id`。
5. 檢查語法、必填欄位、來源、重複 id，並在瀏覽器測試分類、搜尋、直接連結、返回首頁、窄螢幕。
6. 回報新增檔案、測試結果及未驗證事項；不得聲稱未執行的測試已通過。

## 修改限制
只修改任務所需內容；保留既有文章 id 與網址，不任意重構。使用 textContent 渲染資料，不插入未經處理的 HTML。外部來源只接受 HTTPS。不得提交密碼、金鑰或私人資料。無授權不得推送或部署。若需求與規則衝突，先提出差異。

## 驗收清單
- [ ] 資料欄位完整、id 唯一、分類有效
- [ ] 文章有來源且章節符合類型
- [ ] 首頁自動出現新文章，搜尋中英文皆可找到
- [ ] 文章直接網址、返回首頁與分類正常
- [ ] 手機無橫向溢出，鍵盤可操作
- [ ] 無 JS 錯誤、無失效本地路徑
